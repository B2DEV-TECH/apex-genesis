## Supervisor architecture

A single Node supervisor (`runtime/supervisor.mjs`) is the only evaluator of
autonomous runs. It proves ownership twice: with a local lock file and with an
Oracle lease (90 s, renewed every heartbeat) in `apxgen_autonomy`. Oracle owns the
policy, admission, deterministic seeds, the command queue, the operations log and
the publication ledger. Evolution itself stays in `apxgen_evolution`. Organisms of
an autonomous run can only be claimed with the lease token (ORA-20075 otherwise).
The publisher (`runtime/publisher.mjs`) uploads immutable hashed objects, verifies
them over public HTTPS, then moves one pointer. The watchdog
(`runtime/watchdog.mjs`) restarts the supervisor task after a crash or hang, never
after a deliberate stop. The APEX page and the CLI (`runtime/genesisctl.mjs`) only
queue commands. No broker, container or extra scheduler is used. The Oracle job
`APXGEN_AUTONOMY_TICK` records admission state only.
[Operations guide](../operations/autonomous-operation.md).

| `B2DEV-Genesis-Supervisor` | Installing user, InteractiveToken, LeastPrivilege; not SYSTEM, no stored password | At logon of that user | IgnoreNew, no time limit, BelowNormal, restart 3 × 1 min, runs on battery, no wake |
| `B2DEV-Genesis-Watchdog` | Same | Every 5 minutes | IgnoreNew, 2-minute limit, BelowNormal, runs on battery, no wake |

The installer tries S4U first. Windows refused it for the standard user, so the
tasks use the Interactive logon type through `conhost.exe --headless`. The lab
therefore runs only while the user is signed in. No power, sleep or hibernation
setting was changed. Exported task XML contains no Password element.
[Evidence](../testing/autonomy-tasks-evidence.json).

## Default autonomous configuration

GA_ONLY; 12 organisms × 100 generations. INDEPENDENT_THEN_LINEAGE runs five
independent seeded runs, then lineage runs from the previous final checkpoint.
Other limits:

* Base seed 20261020.
* One active run (check constraint).
* Daily cap of 300 generations and a 600 s cooldown.
* Generation interval of 60 s.
* Stagnation window of 25 with action CONTINUE.
* Storage budget of 440 of 500 MiB.
* At most 3 recovery continuations per run.

Publication is enabled on the LAB owner: it checks every 5 min and publishes after 10
new completed generations (at most every 15 min) and on completion. The pointer
heartbeat is 20 min. Paid AI is fixed off by a check constraint (`paid_ai=0`). The
fitness definition is never rewritten. The live page compares scores only within
one fitness definition.

## Publication and exhibition

The dataset is in R2 bucket `b2dev-media` under `genesis/live/v1/`, served from
`https://b2dev.tech/media/genesis/live/v1/latest.json`. Run and catalog objects
are immutable and named by SHA-256; only the pointer changes. The workflow is:

1. Snapshot completed generations.
2. Scan for secrets and check the allowlist.
3. Upload the immutable objects and verify each over HTTPS.
4. Upload the pointer and verify it.
5. Record the result as LIVE, or as FAILED/ROLLED_BACK with backoff.

TEST-labelled runs never reach the public bucket.

The exhibition page is `https://b2dev.tech/genesis/live.html`, proposed in website
PR B2DEV-TECH/b2dev.tech#4. It also makes the worker serve the pointer with
`max-age=0, must-revalidate` instead of the year-long immutable header. Until that
PR is reviewed, merged and deployed, the live page is not in production. It was
verified locally against the real production R2 data on desktop and mobile. The
recorded archives at `/genesis/index.html` are unchanged.

## Remaining risks

* The Interactive logon fallback runs the lab only while the user is signed in.
  Sleep or shutdown pauses it. The page then shows "stale" after 45 minutes.
* The AtLogOn trigger has not been observed through a real sign-in.
* The production live page and pointer cache header wait for website PR #4. Today
  the pointer is served with a year-long immutable header; it is not edge-cached
  and the page fetches it with `no-store`, so new generations still appear.
* Storage grows by every run. When the 440 MiB budget is reached, admission
  stops. Archiving or a larger budget is an owner decision; nothing is deleted
  automatically.
* Open historical AI reservations remain as recorded.
* Proxy fitness reaches its 98.95 ceiling early. Stagnation is recorded and
  continued, and the fitness is not altered to manufacture improvement.
