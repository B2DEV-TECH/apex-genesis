## First complete functional loop

The baseline organism `ef731773b1124b1a870ebcc00c28a0ca` was imported as app 133.
Oracle's seeded mutation produced child `a33d0c2a65404466a10497ea9806ee40`, moving
the filters beside the report. The child was imported into safely recycled app 130.
The previous app 130 was exported, hash-verified and removed through a guarded
workspace API before its slot received new ownership. Its original run, organism,
definition, import record, fixture snapshot and disposal history remain preserved.

Both candidates completed the three tasks with 3/3/6 actions and 1/1/3 navigation
steps. Independent queries verified exactly one intended status/version update and
unchanged records in the other owned partition. Critical/serious axe violations,
unnamed controls, failed focus checks, horizontal overflow and runtime errors were
zero at 390, 768 and 1,440 pixels. Warm-load medians were 135 ms for the parent and
144 ms for the child. Those timing differences establish no human performance claim.

Oracle selected the baseline with task-proxy fitness 89.675. The eligible child
received the same score and was rejected under the preregistered strict-improvement
tie policy. The run consumed two of two materializations and completed generation 1.
Paid requests: zero. This one-seed feasibility test is not an algorithm comparison.

## Remaining acceptance gates

The top-navigation compiler variants report template-option warnings despite
successful validation. Those variants have not passed runtime evaluation; the
successful parent and child both use side navigation. The retained compiler logs
expose these warnings for review before broader trials.

Broader controlled experiments,
native Create/Evolve/Watch controls, safe slot recycling, autonomous integration,
freshly authorized AI integration with the original ledger, production exhibition,
paired research, article and video require their own evidence. No release tag has
been assigned. No paid model request has been made by the new mode.
